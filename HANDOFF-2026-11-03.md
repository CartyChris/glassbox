## Cloud terminal (Terminal tab, top card) — a real shell from any device, no bridge
`api/terminal.mjs` (Node function, `@vercel/sandbox` 3.9.1) creates a Vercel Sandbox (2 vCPU, ≤45 min, not persistent), uploads
`cloud/pfterm.py` (stdlib PTY + file bridge; source shipped as `api/_pfterm.mjs`, regenerate with `dev/pass38/gen-pfterm.mjs`) and
starts it with its token in **env, never argv**. The browser connects straight to the sandbox: Vercel's PTY WebSocket → pfterm
WebSocket → pfterm SSE. Presets: Claude Code, Codex, Gemini CLI, OpenCode, Oh My Pi (`omp`), Qwen, Kimi, Aider. Phone key row.
"Send latest creation" / "Pull /project into Creations" use pfterm's file API. "Connect your own pfterm host" works for any
machine (`/cloud/pfterm.py` is served for download).
**Off until the owner sets `GLASSBOX_TERMINAL_CODE` (8+ chars) in the Vercel project** — sandboxes bill the deployer. Gates:
same-origin, HMAC-signed HttpOnly SameSite=Strict cookie (12 h) earned by the code, 8 code tries / 10 min / IP, 6 creates / hour
(per instance), names `^gbt-…$`, minutes clamped, extend ≤15. The live sandbox path can only be checked once the code is set.
Verified locally: real client + local pfterm — `echo $((6*7))` = 42 over WebSocket (after a deliberately dead first endpoint) and
over SSE with WebSocket disabled; exit reported; text + binary file round trip byte-exact; `../escape` 400; no token 401.
