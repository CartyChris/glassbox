## 4 · Ollama from the Vercel site — the real causes, measured on this Mac

1. `OLLAMA_ORIGINS=*` was set, but the server had been running since 26 Sep, so it answered **403**. The
   variable is read only at start.
2. **`osascript quit app "Ollama"` is ignored** by the hidden menu-bar app, and the app **respawns
   `ollama serve` with its old environment**. Killing the server alone changes nothing.
3. **Fix:** `pkill -x Ollama; pkill -x ollama; open -a Ollama`. Verified: 200 + ACAO for the Vercel origin,
   preflight 204.
4. Chrome 142+ **Local Network Access**: a public site needs a user "Allow". The Claude app's browser pane
   denies it by policy, so the pane can't prove the last step. `lnaPermission()` reads the state (the names
   `local-network-access` / `loopback-network` / `local-network` all work in Chrome 152), and requests use
   `targetAddressSpace:'local'`.

Code: `ollamaFixCommands(origin, os)` (pure; adds the site to `OLLAMA_ORIGINS` rather than overwriting; never
`*`), `ollamaAutoWatch` (reconnects within 3 min), and the rewritten `renderOllamaHelp` (async).
