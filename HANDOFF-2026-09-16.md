## Layout and the one hard rule

One file, no build step: `GlassBox.html`. It is mirrored **byte-for-byte into four places** after
every change:

```
gb-repo/GlassBox.html      gb-repo/index.html
glassbox-deploy/GlassBox.html   glassbox-deploy/index.html
```

`md5 -q` all five and expect one unique hash. `check.py` sits beside the file and is the static
gate — it must print OK after every edit.

`window.__gb` is the only way to drive or inspect the app from outside. Browser automation runs in
an isolated world, so **anything you want to test must be exported there.**

## `check.py` — 12 gates, each positive-controlled

It is not just a syntax check. In order: the script block ends where a browser thinks it does;
JS parses (`node --check`); no duplicate top-level declarations; **no duplicate `__gb` export
keys**; **no empty catch around a persisting write**; **no `fetch()` without an abort signal**; no
duplicate DOM ids; every tab has a section; no orphan ids wired at boot; **both launcher health
tokens present and inside the first 4000 bytes**.

Two flags:

```bash
python3 check.py --stamp     # set APP_BUILD to a content hash
python3 check.py --release   # FAIL if APP_BUILD is stale
```

Neither runs by default — a hard gate on every edit would fire constantly mid-work.

**The guards match the BLANKED source** (comments and strings stripped by the lexer), not raw
text. An earlier version matched raw and a comment merely mentioning `IDB.set(` flagged its own
enclosing block. If you add a guard, match `scan`, not `body`, and **skip the `GAUNTLET_SABOTAGE`
span** — it is deliberately broken code and fires every detector.

## APP_BUILD — why it exists and why it must be stamped

`pwaCheckUpdate` fetches the served page, regexes `APP_BUILD` out of it, and compares against the
running copy. **It went unchanged across five shipped commits**, so every installed PWA compared a
value to itself, concluded it was current, and never offered the update — which is why a phone
needed deleting and re-adding to pick up a deploy.

It is now a content hash of the script body with the `APP_BUILD` line stripped, so it changes if
and only if the code changes. **Stamp before every deploy.**

## The desktop app — read before touching it

`desktop/build-desktop.sh` builds and verifies all three artifacts: `GlassBox.app`,
`GlassBox-macOS.dmg`, `GlassBox-Windows.zip`. **Never build them by hand.** Both downloads had
silently rotted:

- the bundled page was **30,253 lines against the then-current 53,909** — five months that never

- the launchers confirmed the server was up by grepping the served page for the window title

  started its server, failed its own health check, said *"Could not serve GlassBox.html"* and
  quit. **Nothing inside the web app could detect either.**

There are now **two health tokens** near the top of the page, both enforced by `check.py`:

| token | why |
|---|---|
| `glassbox-jet-v1` | what every launcher shipped from now on greps for. Exists for this contract alone, so a rename can never break it. |
| `GlassBox — Reasoning Studio` | **kept deliberately.** Already-installed copies of GlassBox.app grep for it and would otherwise fail against any newer page. |

Both must stay within the **first 4000 bytes** — that is all the probe reads.

## Invariants — breaking any of these is a regression

- **Nothing the user did not write runs on this origin.** Sandboxed iframe, no
  `allow-same-origin`, and that holds for pop-outs. Gauntlet cases enforce it.
- **A new tab must be added to `TAB_GROUPS`**, or it falls out of the grouped bar entirely.
- **Any nav or list must be derived from its data table**, never typed out. This file has produced
  that bug four times.
- **Grep a class or attribute name before introducing it.** Collisions have caused invisible UI
  four times.
- **A preset must reset the fields it owns before applying.** Presets that only add are
  accumulators.
- **`store.set` and `IDB.set` failures are loud.** `IDB.set` **returns false, it does not throw** —
  a try/catch around it catches nothing.
- **Reassigned top-level `let`s exported on `__gb` need `get`/`set`.** A getter-only export makes
  writes silently no-op, which has produced a vacuously green test twice.
- **A gauntlet case must call through the same export its sabotage replaces.** `foo()` calling
  module-scope `bar()` is unaffected by sabotaging `g.bar`. **This trap has now bitten three
  times.**
- **`gauntletRun` is strictly synchronous** (`got=c.run()`, no await). An async case hands
  `expect()` a Promise and passes while proving nothing.

## The harness layer (newest, most likely to be built on)

| function | what it is |
|---|---|
| `toolCatalog()` / `toolSource()` / `toolInvoke()` | one catalogue and one dispatcher over OCR, OpenBot and connector/MCP tools. `toolSource` is **pure** — an unmatched name returns `null`. |
| `reactParse()` / `reactDecide()` / `reactRun()` | Thought/Action/Observation. Parse and decide are **pure and synchronous** so the suite holds them; only `reactRun` touches the network. |
| `dodProblem()` / `dodReady()` | definition of done. `runSwarm` **refuses to start** without ≥2 checkable criteria. |
| `bidScore()` / `bidCalibration()` / `bidAward()` | confidence per unit cost, with a floor, discounted by how well a member's past claims matched reality. |
| `harnessAudit()` | probes six layers from live state and names the **thinnest**, never an average. |

**Scoping that must not be lost:** plain ReAct does **not** beat chain-of-thought on knowledge
tasks (27.4 vs 29.4, CoT-SC 33.4 in the paper). Its win is grounding. Actions travel as **text**,
not native tool-calling, because the wire format differs per provider and local models often expose
none — that was a choice, not an oversight.

**Two claims deliberately not repeated as fact:** "context is ~80% of agent success" does not
survive measurement in its strong form (2026 harness benchmarks find stronger models still win with
the harness held constant; the "80%→100%" figure behind it is **n=5**). Capability belongs to a
*model-and-harness pair*. Karten's Turing→von-Neumann framing **is** carried, and it shaped the
design: the context layer counts **reads and writes separately**, because read-only context is a
better-briefed Turing machine rather than a different class of machine.

## Environment traps that will waste your time

- **The browser pane is usually hidden**, which makes the page measure 0×0 and
  `requestAnimationFrame` **never fire**. Take a screenshot first, then measure. This applies to
  production code too, not just probes — the accessibility observer needed a `setTimeout` backstop
  for exactly this reason.
- **Cache-bust every reload** (`?v=N`). Re-navigating the same URL serves a stale copy.
- **To test a cold profile, use a DIFFERENT ORIGIN.** `http://127.0.0.1:8765` and
  `http://localhost:8765` have separate storage. Calling `indexedDB.deleteDatabase()` from a live
  page **wedges IDB at origin level**, survives reloads and new tabs, and looks exactly like a
  boot crash. I lost time diagnosing a "first-run crash" that was my own test method — the
  pre-change build failed identically.
- **`go()` takes the `data-view` value (`webos`), NOT the section id (`view-webos`).** Passing the
  section id silently activates nothing and every measurement after it is meaningless.
- **Let the accessibility observer settle before counting.** A nameless-control count taken
  straight after boot reads non-zero because the pass drains on a 250ms backstop.
- `vercel deploy --prod` **without** `--scope cloud-ops-game-time` fails "Not authorized". A bad
  git author email presents as a false "upgrade to Pro" prompt — it is not a plan limit.
  **Chris is on the free plan and does not want to upgrade.** Keep the commit author as
  `chriscarty123@gmail.com`.
- The working directory is under **iCloud Drive**. `git` can return
  `fatal: .git/index.lock write error: Operation timed out` **while the commit actually
  succeeded**. `rm -f .git/index.lock`, then compare `git rev-parse HEAD` with `origin/main` —
  do not re-commit on the strength of the error text.
- **Skip the GAUNTLET region (~2.2k lines) in any code audit** — deliberately broken `broken:`/
  `anti:` code; every hit is a false positive.
- The harness cannot reliably click into a sandboxed iframe. Inject a probe that dispatches a real
  DOM click and reports via `postMessage`.

## Measurement discipline — this is where most mistakes came from

Almost every wrong conclusion in the last several passes was a **bad probe**, not a bad build.

- **Alternate and repeat, or do not report a number.** A pane-batching optimisation measured
  "29.6% faster" on first run and that was pure ordering artifact — the warmed path ran second.
  Ten alternating rounds said 768.6ms vs 776.9ms: no gain. **It was reverted**, and `setPane` was
  diffed byte-for-byte against the shipped version to prove the revert was clean.
- **Don't benchmark with `.repeat()` data.** It said deflate saved 98%; real varied content said
  63–67%.
- **Control one variable before attributing.** Twice a "regression" reproduced identically on the
  pre-change build.
- **Verify against the system that owns the thing.** A pass once recorded "all 5 video model ids
  are dead" after checking them against the wrong catalogue.
- **Open the abstract page, never the search snippet.** A previous pass nearly cited a paper that
  had been withdrawn. Research agents in this project have fabricated attributed statistics twice.

## Open — what I would do next, in order of value

1. **The Trigger layer is the thinnest in the app's own audit** — one event source (the PWA update
   poll). Almost everything still starts because someone pressed something. `harnessAudit()` names
   this; acting on it is the highest-value harness work left.
2. **`reactRun` has never been exercised against a live model.** The parser and every decision
   branch are tested exhaustively and synchronously; the loop's round trip is not. Run it once
   against a cheap hosted model on a task with a real tool call, and watch the logs at all three
   boundaries.
3. **Native tool-calling as an opt-in path** alongside the text protocol, for providers that
   support it. The research for this is already done and specific — OpenAI reassembles fragmented
   arguments by `index`; Anthropic indexes into the whole content array; `index` means different
   things on the two wires; do not gate dispatch on `finish_reason`.
4. **Self-verification before exit** — intercept the agent before it is allowed to finish and force
   a verification pass. Measured elsewhere as the single highest-attributed harness gain.
5. **182 empty catches remain and ~180 of them are correct** (a failed delete loses nothing; a
   failed probe *is* the answer). `check.py` now blocks new ones around persisting writes. Do not
   "fix" the rest en masse — that would be a regression.
6. **42 getter-only exports remain, deliberately.** Only add a setter where the invariant applies:
   a reassigned top-level `let`.
7. Accessibility beyond naming: contrast is clean (a sweep of 572 elements found exactly one
   failure and it was fixed), but there has been no screen-reader pass and no reduced-motion audit.
